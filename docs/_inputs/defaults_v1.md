## 演示配置 DEMO-CFG-1（仅用于本轮比赛演示，非最终批准默认）
D01 K=3；结果和界面显示"K=3（演示配置v1）"。
D02 启用 rules.md 7.1、7.2 的全部建议作为 DEMO-CFG-1；计算结果引用该配置版本。
D03 as_of 用带时区的时刻（ISO 8601，+08:00）；快照阶段取值：DAY_START（当日事件均未计入）/ AFTER_EVENT(n)（已计入至第 n 个事件）/ DAY_END。
D04 资金检查期间：从 as_of 到"最后一笔目标相关收付款日"与"其后第一笔已确认收入到账日"中较晚者；无后者则到 2027-01-01；任一必要事件晚于 2027-01-01 → 暂无法完整判断。

## 资金与时间轴
D05 每个节点计算 G=C−L−N−O，H=G−M，U=H−A。L+N+O+M>C → 保护性资金缺口；否则 U<0 时：出现在快照或用户修改分配/预留之后 → 分配冲突；出现在某笔流出之后 → 付款缺口（金额 −U，相关项目为该流出）。
D06 本目标付款：先按覆盖关系核销预留 q；剩余部分先冲减 A，再用未分配资金。
D07 不属于本目标、也无预留覆盖的支出只能用未分配资金；不足即付款缺口；不得自动挪用 A 或保护资金。
D08 未来各期生活预留挂在指定预计收入上，收入到账（或在假设时间线中到账）时建立；预留到期剩余默认不释放（release_at_end=false）。
D09 机动预留在活动结束次日释放（案例另有规定除外）；首版第二目标只是一条固定占用 O（名称+金额，无付款时间）。
D10 同日先后未知：流出排在不能确定已到账的流入之前；同日多笔流出先后未知 → 报告日级累计缺口及相关项目列表。
D11 界面显示最早缺口（日期、金额、相关项目、计算依据），可展开检查期间内全部缺口节点。

## 成本、价格与候选
D12 付款即返、金额与日期明确、不依赖后续行为的返现计入 R 并参与排序；依赖后续条件的不计入 R，另显示"若到账"。
D13 价格依据优先级：同一购买日的有效模拟报价 > 已确认的合格预测 > 有效参考价（标估算）> 待填。
D14 预测估算按"项目+购买日"确认，可批量确认。
D15 候选由案例数据直接列出完整组合并带固定编号（C01…）；程序只做校验、排除和排序，不做排列组合生成。
D16 相容性约束字段：arrive_before_show_min、lodging_nights_required、return_after_show_min、seat_tier_allowed、lodging_max_distance_km、refundable_required。
D17 优惠字段：type（立减/满减/折扣/返现/返券）、scope、threshold、valid_from、valid_to、applies_at（下单/付款）、max_uses、stackable_with、rounding；舍入规则未知 → 条件不完整。

## 确认与状态
D18 确认时建议分配额 = min(剩余计划目标付款中未被预留覆盖部分, 当前 U0)；不足部分记为挂在指定预计收入上的计划分配；存在缺口或约束问题的方案只能存为草案，不写入正式分配。
D19 三类状态。计划状态：暂无法完整判断 / 发现付款缺口 / 存在约束问题 / 按当前假设可行 / 已暂停 / 已取消。优化状态：未比较 / 部分可评估 / 已完成-有可行方案 / 未找到已知可行方案。确认状态：未选择 / 待用户确认 / 已确认 / 草案。计划状态优先级：暂无法完整判断 > 发现付款缺口（含保护性资金缺口）> 存在约束问题（预算超限、分配冲突）> 按当前假设可行；已暂停/已取消为用户决策，单独显示并保留已有义务。
D20 未确认方案时，资金日历页显示"草案预览"（基于用户初始描述或当前选中的候选），明确标注"预览，未确认"。

## 情景、预测与每日参考
D21 消费类别：餐饮、本地交通、日用、娱乐、目标相关、收入、退款、转账；每类注明是否由生活预留覆盖、是否属"非计划支出同口径"。
D22 今日情景替换额 = max(0, 今日情景额 − 今日已发生同口径支出)。
D23 情景总额按分四舍五入，余数按 7.1 规则分配。
D24 预测样本取预测起点前最近一段连续可比日级样本；不足 14 个 → 历史不足。
D25 Holt 中间值每步递推后按 ROUND_HALF_UP（.5 远离零）保留 12 位小数；TS 用 decimal.js，Python 用 decimal。
D26 9/1 只按已确认安排计算每日参考；10/1 同时计算"仅已确认安排"和"近月情景"，展示较低者并注明限制来源。
D27 仅在存在已确认方案时计算每日参考金额；无已确认方案时显示"确认方案后可计算"，不显示 0。

## 比赛对齐（以工行杯规则为准）
C1 项目书用简体中文；若香港赛区要求繁体，用 OpenCC（s2hk）转换后人工抽查术语。
C2 结构：前侧分析（市场、竞品、工行/工银亚洲现状、用户分析）→ 主体创新方案 → 后侧分析（商业模式、财务测算、落地规划、风险防控、营销方案）→ 附录；含附录 ≥40 页，图表 ≥15 张（目标 20 张）。
C3 财务测算 = 基于原型实测调用量的成本测算 + 政策卡第十节的试点评估公式 + 标明"示意参数，非预测"的敏感性分析；不预测银行收入、存款或消费增长。
C4 用户研究：可选小问卷（目标 ≥30 份）与团队成员亲历案例，均如实标注样本性质；未做时以"待验证假设+访谈计划"呈现；严禁编造任何调研数据。
C5 香港赛区适配：Demo 保持人民币单币种；项目书增设"香港适配路线图"，纳入工银亚洲公开资料，跨币支付列为后续验证。
C6 项目书中每项功能按"规则已确认/已实现/测试通过/真实用户验证"标注状态，以测试运行记录为准。
C7 "产品建议"按"面向工行（含工银亚洲）的产品落地建议"撰写。
C8 作品名称：品牌名+一句话定位，不超过 25 字。
