## 4. 本轮发现的问题

### 4.1 【高】每日参考「不建议新增」被渲染成 0.00 元（真实缺陷）

- **用户影响**：用户会把"系统不建议你今天再花钱"读成"系统算出今天还能花 0 元"——两者含义相反，属于会影响财务判断的误导性展示。
- **根因**：引擎在 `display='NOT_RECOMMENDED'` 时**故意返回 `amount`**（值 0，用于携带判定依据，见 `src/engine/daily/index.ts` 的 `blockedAmount`）。界面三处主展示位原先都写成 `amount == null ? 状态文案 : 金额`，于是 0 被当作"有效金额"渲染成"0.00 元"，而"当前不建议新增非计划支出"从不显示。
- **验证**：把旧逻辑临时还原后，新增的端到端断言立即失败（`element(s) not found`）；恢复修复后 17 条 spec 全通过。**这不是推测，是双向验证过的事实。**

### 4.2 【中】上一轮把 T020-02／T020-04 误标为"每日参考金额的展示分支"

- 查 `docs/traceability.csv` 与 `docs/_work/test_layers.md`：这两条属于 **R020 价格预测**，要求分列训练 SSE 与各 h 的回测 MAE_h（含样本数与步长）；未覆盖原因是**界面没有这两组指标的展示位置**，与每日参考无关。
- 该错误让"高风险区域"的定位失真：真正有风险的是每日参考（见 4.1），而它恰好没有对应子用例。

### 4.3 【中】图 22 右侧两列被画布裁切

- 该图十列宽度合计 1140px，而 SVG 画布固定 1000px → "取整金额""确认"两列被切掉，只露出半个"取"字。
- 影响：附录 A.9 的核心证据图不完整，评审看到的表格缺列。

### 4.4 【低-中】图 10／11／12／23 落款写"模拟数据"

- 这四张是架构/执行流程/数据流/状态树，属"按规则与代码人工整理"，与"模拟案例数据"性质不同，属来源标注不实。

### 4.5 【低】图 3／图 8 纵轴单位写"分"，数值实为元

- `barChart` 的默认单位是 `'分'`，而传入的数值已由 `formatCents` 折算为元（如 660.00）。图 3 与图 8 都受影响。

### 4.6 【已核实】官方提交要求：GH03 页本轮重新打开

本轮实际抓取 `https://www.gonghangbei.com/news/view/131.html`（HTTP 200，发布时间 2026-09-20），正文载明：

**该页未提附件格式、大小、页数或评分标准**，与正文"官方未公布格式与大小"的表述一致；"≤20MB／PDF"仍只能作为团队自设标准。

### 4.7 【中】附录 B.3／B.4 的改进会被生成命令覆盖（设计问题）
