# 确认机制与行动清单

## 为什么需要确认通道

"未确认的模型推断不得写入确认记录"是硬约束（AGENTS.md §3、D60）。自然语言抽取的每个值都只是**待确认值**：它可以显示、可以高亮原文出处、可以与案例数据比对，但在用户确认之前不得进入计算输入。

## 确认链路

![确认与行动清单流程](../figures/fig_confirm_flow.svg)

1. **选择候选**：`SELECT_CANDIDATE` 只改变"当前选中的候选"，不写入正式安排、不增加输入版本（D29、SG-32）。
2. **建议分配额**：ΔA 在 `[0, max(0, W − A0)]` 内取满足"确认后全部节点 U 的最小值不降低"的最大整数分；条件随 ΔA 单调，用二分求解。界面名称为"建议分配额（不减少今日可额外支出）"（D18、D46）。
3. **写入正式安排**：`CONFIRM` 写入时输入版本加 1；只存草案时不加。重复提交同一确认（同一候选、同一方案版本、同一输入版本且主记录仍是该方案）不重复写入、不加版本；引用的输入版本已过期时先按当前版本复查，通过才写入（D63、SG-64）。
4. **冻结行动清单**：确认时按当时数据冻结任务编号、渠道、购买日、付款日与优惠；之后风险与可行性按当前输入重算，清单不自动改变（R017 第 8—10 条、D77）。
5. **版本失效**：输入变化后，早于当前版本的确认记录一律标"需重新确认"，不直接用于判断（D60）。

## 行动清单的字段与取舍

任务编号为"候选:价格项序号"；任务状态在本版恒为"待购买"，因为案例中没有把购买记录关联到任务的字段（SG-66）。不列入已购项目的另一报价（D75）、确认免费与不适用的项目；取消后 `cancellable` 为 true 的价格项不再显示。清单同时给出该任务涉及的优惠与需要复核的条件：价格依据不是有效期内的报价、为估算或金额未知时提示复核价格，用了优惠或依据预测估算时提示复核优惠条件。

## 待确认差异

新估算只取**已确认价格项按当前输入重算**的金额，与确认时冻结金额不同时按费用项目汇总差额，行动清单不变；其他候选的价格（含未经确认的预测）不计入（D77）。

## 本轮实现状态

引擎侧的确认写入、草案保存、版本失效与行动清单均已实现，并有向量与单元测试覆盖；自然语言侧实现了提取、追问、草稿、确认记录构造与解释句校验，可离线回放。

自然语言的实际链路是：**提取 → 追问 → 草稿 → 用户逐字段确认 → 把确认值写入案例输入的 `confirmations[]`（`input_version` 取该案例代表的版本）→ 用 `caseFileSchema` 复验 → 重新计算**。因此确认值确实参与了引擎的确认判断（结果 `userConfirmations` 的状态为"当前版本"），未经确认的模型推断不会被写入，也不会进入计算。

本轮**没有**实现的是"在一次计算会话内追加确认记录并自动增加输入版本"：D29 的操作白名单里没有写入确认记录的操作，D58 又禁止界面使用 `PATCH`，所以每追加一次确认都通过**重建输入版本并重算**完成（方案 A）。是否新增该操作类型属于正式数据契约变更，需团队裁决，本稿不擅自实现。
